# 1. 개요

관리 대상 데이터를 **도메인(Domain)** 단위로 최상위 분류하고, 그 아래로 **다축 분류체계(Multi-axis Classification)** 및 트리 구조의 분류 노드를 구성한다. 도메인은 하나 이상의 **분류축(ClassificationAxis)** (예: 부서 축, 직군/고용형태 축, 카테고리 축)을 가질 수 있다. 각 노드는 자신만의 **필드(Field)** 를 정의할 수 있으며, 정의된 필드는 하위 노드에 자동으로 **상속**된다. 필드는 관리자가 자유롭게 추가/수정할 수 있는 동적 스키마이다.

예시 (다축 분류):

**도메인:** 임직원
- **기본 분류축 (부서 조직도):**
  ├─ 영업본부 (Node)
  └─ 개발본부 (Node)
     ├─ 프론트엔드팀 (Node)
     └─ 백엔드팀 (Node)
- **서브 분류축 (고용형태 축):**
  ├─ 정규직 (Node)
  └─ 비정규직 (Node)

레코드는 부서 조직도의 `백엔드팀` 노드를 주 분류로 가지면서, 동시에 고용형태 축의 `정규직` 노드에 서브 매핑될 수 있다.

# 2. 핵심 개념 정의

| 개념 | 설명 |
|---|---|
| **Domain** | 분류체계의 최상위 마스터 데이터 관리 단위 (예: 임직원, 고객, 상품). 레코드 식별/표시 키 필드 지정. |
| **ClassificationAxis** | 도메인 하위에 존재하는 분류 기준 축. 도메인은 1개의 기본 축(`isDefault=true`)과 여러 서브 축을 보유 가능. |
| **ClassificationNode** | 분류축을 구성하는 노드. 부모 노드(`parent_id`)를 가져 상속 트리를 형성. |
| **RecordSecondaryNode** | 레코드가 주 분류 노드 외 타 분류축 노드에 속할 수 있도록 지원하는 다대다 매핑. |
| **FieldDefinition** | 특정 노드에 정의된 필드 (이름, 타입, 옵션, 필수, 암호화, 유일성 등). |
| **EffectiveField** | 특정 노드 기준으로 자신 + 상위 조상 노드들로부터 상속받은 최종 유효 필드 집합. (Redis/Local In-Memory 캐싱 적용) |
| **DqScoreSnapshot** | DQ 스캔(크론/수동) 실행 시점의 도메인 품질 점수 및 위반 건수 시계열 기록. |
| **Dead-Letter Queue (DLQ)** | 연계(Integration) 실패 시 지수 백오프 재시도 후 최대 횟수를 초과한 실패 건을 격리 관리하는 큐. |
